# 限行数据契约

## 1. 用途

设备每天拉取一个签名 JSON 包，获得当天北京的规则与覆盖度。设备不直接解析政府网页，避免把页面结构变化带到端侧；v2 包结构见[数据契约 v2](../docs/07-data-contract-v2.md)。

- 当前示例：[current.json](current.json)
- 字段定义：[schema/limit-day.schema.json](schema/limit-day.schema.json)
- 消费端设计：[docs/03-software-design.md](../docs/03-software-design.md)

> 截至 v0.1，定时抓取服务尚未实现；`current.json` 是 2026-10-27 的示例数据，请勿当作实时数据使用。
> 现有 v1 示例与 schema 仅用于讨论，无法充分表达各规则适用日、豁免条件、临时变更与可信性；不得用于实际判断。v2 契约设计见 [数据契约 v2](../docs/07-data-contract-v2.md)，本文不修改数据或实现。

## 2. 数据来源

- 权威来源：北京市人民政府通告、北京市公安局公安交通管理局发布信息。
- 示例来源：[北京市人民政府关于实施工作日高峰时段区域限行交通管理措施的通告](https://www.beijing.gov.cn/zhengce/zhengcefagui/202603/t20260323_4564097.html)。
- 设备数据由仓库的定时任务生成；解析失败时保留旧数据并报警，不写入猜测值。
- 限行信息仅供参考，最终以官方发布为准。

## 3. v1 字段说明（历史草案）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `date` | string | 是 | 数据对应日期，`YYYY-MM-DD` |
| `city` | string | 是 | 城市，首版固定 `beijing` |
| `is_workday` | boolean | 是 | 普通工作日标志；不能直接代表限行规则适用日 |
| `restricted_tails` | string[] | 是 | 当天限行尾号；工作日为 2 个，不限行为空 |
| `windows` | object | 否 | 限行窗口与范围；设备有内置默认值，此字段用于审计 |
| `source` | string | 是 | 权威来源 URL |
| `updated_at` | string | 是 | 数据生成时间，ISO 8601 带时区 |
| `valid_until` | string | 否 | 数据有效截止时间 |
| `data_version` | integer | 是 | 契约版本，首版为 1 |
| `notes` | string | 否 | 备注，最多 500 字 |

`windows` 结构：

| 字段 | 说明 |
| --- | --- |
| `local_tail` | 京牌尾号限行窗口 |
| `nonlocal_peak_ban` | 外埠车辆早晚高峰禁入窗口 |
| `nonlocal_tail` | 外埠车辆平峰尾号限行窗口 |

每个窗口包含 `start`、`end`（`HH:MM`）与 `area`（`inside_5th_ring_excluding`、`inside_5th_ring_including`、`all_city`）。

## 4. 更新与校验

1. 每天 00:05（Asia/Shanghai）抓取官方通告；日期或尾号无法确认时不更新。
2. 写入前校验：JSON Schema、日期等于当天、尾号数量为 0 或 2、来源域名白名单（v1 only；v2 必须验签）。
3. 设备每天 00:05 触发拉取，离线则恢复联网后补拉；失败按 1/5/15 分钟重试 3 次，之后每 30 分钟低频重试。
4. 设备只使用日期匹配、在有效期内且依据可信的数据；关键依据缺失时为未知，不能用旧日数据或单独的轮换表判定今天。
5. 手动更新时只改 `current.json`，不要改 schema；提交前用 JSON 工具校验语法。
6. 以上是 v1 流程。v2 的验签、修订号、覆盖度和撤回校验顺序见[数据契约 v2](../docs/07-data-contract-v2.md)，在 v2 实现前不得把 v1 数据用于现场判断。
