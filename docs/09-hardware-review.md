# 硬件接口设计审查与冻结清单

> 2026-10-27 · 草案。根据项目已确认的 RDK X5 Module、ML307N 和 KiCad 10 选择，评审硬件特性规格；不绘制原理图、布板、转换工程或采购。本记录补充 [硬件特性规格](02-hardware-spec.md) 和 [系统设计基线](06-system-design-baseline.md)。

## 1. 基线与证据

既定目标为门岗单车道车牌识别、联网获取当日信息并语音提醒；设备不控制道闸。RDK X5 Module 与 ML307N 是现有硬件，**具体版本、子型号和配件尚待确认**。底板、供电、摄像头、扬声器、天线和外壳均处于方案阶段；现有 KiCad 文件为空骨架，不构成已完成电路设计。

各项结论应附对应型号、文件版本、页码或测量记录。未标明来源的电压、电流、时序、引脚、外设能力和尺寸均为待验证假设，不用于冻结 BOM 或接口。开发板的电源适配器额定值不能直接当成单独核心板的实测电流。

| 证据 | 需要确认 |
| --- | --- |
| 核心板型号、容量与硬件修订 | 接插件、引脚、电源、存储、启动、RTC、可用接口、散热限制 |
| ML307N 完整料号与固件版本 | VBAT、峰值及持续时间、IO 电平、控制时序、SIM、电源状态、音频与网络能力 |
| 模组与核心板官方设计指南 | 推荐电路、时序、保护、连接器、布局与测试条件；参考设计的使用许可 |
| 场地和外围件 | 安装区域与方向、电源与线长、摄像头视角、照明、环境、防护和噪声 |

## 2. 接口边界和评审要点

| 接口 | 方案阶段要回答的问题 | 冻结证据 |
| --- | --- | --- |
| 电源输入 | 适配器输入范围、线损、反接、过流、瞬态、连接方式和维护条件是什么？ | 电源预算、保护器件选型依据、线缆和环境条件 |
| X5 供电 | 核心板需要哪些供电域、最大电压偏差、启动顺序与瞬态裕量？ | 对应硬件版本手册、接口表与负载工况 |
| LTE 供电 | 模组在发射、启动、关机下的电压与瞬态要求是什么？ | 子型号手册、VBAT 引脚测量计划与布局约束 |
| X5 ↔ LTE 控制 | UART、PWRKEY、RESET、状态指示的方向、电平与上电默认态是什么？断电端是否被背供？ | 信号对照表、两端供电状态矩阵、转换器与保护方案 |
| 音频 | 子型号是否提供可用离线 TTS、输出格式是什么？选择模组音频还是 X5 音频？ | 手册、音频链路和桥接功放输出隔离方案 |
| USB 摄像头 | USB 主机能力、端口电流、线长、供电与热插拔条件是什么？ | 摄像头候选规格、负载和接口保护方案 |
| SIM 与天线 | SIM 电平/插拔条件、频段、馈线、天线类型和外壳影响是什么？ | 模组与天线厂商指南、空间布局和射频评审 |
| 存储与 RTC | 模块是否自带存储？启动方式、备份电源和充电条件是什么？ | 确切模块版本资料和启动、断电恢复方案 |

接口表应包含信号名、方向、连接器/引脚来源、正常电压范围、上电与复位状态、异常时的保护、测试点及验证责任角色。任一侧未供电、线缆插拔和复位时都要检查背供和不确定电平。引脚号未核验时保持空白，不从开发板接口推断核心板引脚。

## 3. 电源、散热与机壳

电源树先保留两种候选：主计算与外设独立供电，或共享主轨并实施负载隔离；不得在转换器、负载和线缆能力未确认时选择其一。对每条轨记录典型、连续最大、瞬态峰值及持续时间，并核算可能同时发生的负载。输入侧按最低输入电压、线损及各级最低效率估算，再考虑器件温度降额与余量；峰值是否同时发生要有依据。

验收点应在实际负载引脚而非仅转换器输出，测量启动、蜂窝发射、摄像头和音频共同工作时的电压、跌落、纹波与温度；限值以各实际器件手册和确认工况为准。过流、反接、ESD 和浪涌需要分别定义测试边界，不能以安装了某个保护器件作为合格证明。

室外防护目标与散热开孔可能冲突：先明确安装环境、防护等级及所选连接器、天线和散热方式，再建立整机防水防尘与温升验证方案。射频净空、馈线参考平面和接地按实际天线及叠层评审，不预设通用禁铜距离。

## 4. 设计门禁

1. **输入资料门禁**：登记两块现有硬件的确切型号、官方资料及版本；确认门岗场景和供电条件。
2. **架构门禁**：完成电源树候选对比、接口矩阵、音频路径和设备边界；逐项标注假设、验证责任角色和证据。
3. **规格冻结门禁**：完成电源与散热预算、失效处理、结构及安装约束、隐私边界和可测性评审；未确认参数不得转化为固定器件或走线要求。
4. **后续实施门禁**：只有在用户允许进入实现、规格冻结及工具链兼容验证后，才开展原理图和 PCB 设计。

## 5. 工具与版本

项目选定 KiCad 10；现有工程以 KiCad 8 格式初始化，跨版本打开、升级提示、保存后的差异和兼容性均尚未验证。后续如获准实施，应在保留原文件和可回退版本的前提下评估，项目统一使用经确认的工具版本。本记录不启动 KiCad、不打开或保存工程。
